## What the numbers mean

- **The provider is the turn.** Client wall time and the kernel's own
  transcript→model span differ by under 1 ms (2 810.6 vs 2 809.8 at p50), so
  Evie's bookkeeping is not the cost; the remote model is.
- **Variance dominates.** An earlier 20-trial run on the same build measured
  p50 6 428 ms with the same provider and prompt, while this run measured
  2 811 ms. Any change worth claiming must be larger than that spread, so no
  "faster now" claim is made here.
- **The tail is the felt delay.** p95 10 s / max 14.7 s is the number that
  makes a typed turn feel stuck; it is provider queueing/retry, not local work.
- **Ack and stop are separate budgets and they pass**: first feedback ≤1 500 ms
  and stop ≤2 s are measured by S18/S22, which never touch the provider.

## Open, named honestly

- Time-to-first-token is **UNVERIFIED**: the kernel measures the full model
  span, not the first streamed token. Streaming replies into TTS is the change
  that would move perceived latency, and it is not in this build.
- The next real lever is provider-side (model choice / region / streamed
  tokens), not more local micro-optimisation; connection reuse was considered
  and is unmeasurable against the run-to-run spread above.
